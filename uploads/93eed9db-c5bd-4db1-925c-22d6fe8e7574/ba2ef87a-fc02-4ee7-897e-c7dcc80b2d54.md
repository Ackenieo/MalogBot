# DLC 格式技术报告

## 1. 概述

**DLC (Deep Learning Container)** 是高通 **SNPE (Snapdragon Neural Processing Engine)** SDK 定义的专有深度学习模型格式，用于在高通骁龙平台（Snapdragon）的异构计算单元上部署神经网络模型。

| 项目 | 说明 |
|------|------|
| 全称 | Deep Learning Container |
| 开发者 | Qualcomm（高通） |
| 所属 SDK | SNPE (Snapdragon Neural Processing Engine) |
| 底层格式 | 二进制，基于 Protobuf 序列化 |
| 部署目标 | 骁龙 CPU / GPU / DSP / NPU |
| 开源状态 | 专有闭源格式 |

---

## 2. 转换流程

```
PyTorch / TensorFlow / Caffe / ONNX
          │
          ▼
    ONNX 模型（中间格式）
          │
          ▼
snpe-onnx-to-dlc / snpe-tensorflow-to-dlc / snpe-caffe-to-dlc
          │
          ▼
   DLC 模型（最终部署格式）
```

### 2.1 典型转换命令

```bash
# ONNX → DLC
snpe-onnx-to-dlc \
    --input_network model.onnx \
    --output_path model.dlc

# TensorFlow → DLC
snpe-tensorflow-to-dlc \
    --input_network model.pb \
    --output_path model.dlc
```

### 2.2 实际案例：Qwen3-0.6B 转换

来源：Qwen3 ONNX/DLC 转换项目（详见同目录 README.md）

| 阶段 | 工具 | 结果 |
|------|------|------|
| PyTorch 导出 | PyTorch → ONNX (opset 18) | `qwen3_snpe.onnx` + `.data` |
| ONNX 降级 | 手动修改算子 opset 18 → 13 | 修复 ReduceMean/Reciprocal/Reshape |
| DLC 转换 | `snpe-onnx-to-dlc` | `qwen3_final.dlc` (2.83 GB) |

## 3. 算子兼容性

SNPE DLC 格式对 ONNX opset 版本有严格限制：

### 3.1 版本要求

| 组件 | 版本 |
|------|------|
| SNPE 2.29 支持的最高 Opset | **13** |
| PyTorch 默认导出 Opset | 18 |
| 差值 | 5 个版本差距，需手动降级 |

### 3.2 需要降级的算子

| 算子 | Opset 18 | Opset 13 | 修复方法 |
|------|----------|----------|----------|
| **ReduceMean** | axes 是第二个输入 | axes 是属性（attribute） | 将 axes 从输入移到属性 |
| **Reciprocal** | 版本 13 | 版本 1-6 | 替换为 `Pow(x, -1)` |
| **Reshape** | 有 `allowzero` 属性 | 无此属性 | 删除 `allowzero` |

### 3.3 兼容的算子（无需修改）

Transpose、MatMul、Softmax、Sigmoid、Add、Mul 等在 opset 13 和 18 之间无变化。

### 3.4 算子统计（Qwen3-0.6B 案例）

| 算子 | 数量 | 是否修改 |
|------|------|----------|
| Add | 253 | 否 |
| MatMul | 253 | 否 |
| Mul | 422 | 否 |
| Pow | 226 | 替换 Reciprocal |
| ReduceMean | 113 | 是（axes 输入→属性） |
| Reshape | 168 | 是（删除 allowzero） |
| Transpose | 141 | 否 |
| Softmax | 28 | 否 |
| Sigmoid | 28 | 否 |

## 4. DLC 格式特点

### 4.1 优势

- **异构加速**：支持 CPU + GPU + DSP + NPU 协同推理
- **量化支持**：支持 FP32、FP16、INT8 量化，减小模型体积
- **硬件优化**：针对骁龙架构深度优化算子执行效率
- **DLC 容器化**：模型权重和计算图打包为单一文件，便于分发
- **Snapdragon 生态**：与 QNN、Adreno GPU、Hexagon DSP 深度集成

### 4.2 局限性

| 限制 | 说明 |
|------|------|
| 平台绑定 | 仅支持高通骁龙平台 |
| 闭源格式 | 无法直接查看或修改 DLC 内部结构 |
| 算子支持有限 | 部分 ONNX 算子不支持，需手动替换 |
| Opset 版本滞后 | 支持的 ONNX opset 版本远晚于最新版 |
| 调试困难 | 错误信息不够明确，排查问题成本高 |
| 社区支持少 | 相比 TensorRT 等，文档和社区资源较少 |

### 4.3 与常见格式对比

| 特性 | DLC (SNPE) | ONNX | TensorRT | CoreML |
|------|------------|------|----------|--------|
| **开发商** | Qualcomm | 微软/社区 | NVIDIA | Apple |
| **部署平台** | 骁龙设备 | 通用 | NVIDIA GPU | Apple Silicon |
| **格式** | 二进制专有 | Protobuf 标准 | 二进制专有 | mlmodel/package |
| **量化** | FP16/INT8 | 无 | FP16/INT8/INT4 | FP16/INT8 |
| **动态形状** | 有限支持 | 支持 | 支持 | 有限支持 |
| **开源** | 否 | 是 | 否 | 否 |

## 6. 常见问题

### Q1: DLC 能在 x86 CPU 上推理吗？

不能。DLC 专为高通 ARM 设备设计。x86 容器不支持 NPU/DSP 算子（如 GatherNd）。需要在目标 ARM 设备上运行。

### Q2: SNPE 有 Bug 吗？

经验证（Qwen3-0.6B 成功转换），大部分"SNPE Bug"实际上是转换方案不完整导致的：

1. **ReduceMean 问题**：只改 opset 版本号不够，必须完整替换节点
2. **Transpose 问题**：opset 13 和 18 之间无变化，无需修改
3. **拓扑顺序**：删除/添加节点时破坏了计算图依赖关系是最常见原因

### Q3: 转换后模型正确性如何验证？

```bash
# 使用 ONNX Runtime 验证 ONNX 推理
python chat.py  # 检查输出文本连贯性

# 在 ARM 设备上运行 DLC
snpe-net-run --container model.dlc --input_list input_list.txt
```

## 7. 总结

DLC 是高通 SNPE SDK 的专有模型格式，主要面向骁龙平台的 AI 推理部署。其核心价值在于利用高通异构计算单元（CPU/GPU/DSP/NPU）实现高效推理。主要限制是平台绑定和 ONNX opset 支持滞后，转换时需要手动处理算子兼容性问题。
